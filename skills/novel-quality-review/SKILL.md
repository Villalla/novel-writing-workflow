# 小说质量审校（五轮审校法）

## When to use

- 章节初稿（draft）完成，需要修订到 revised / final
- 用户觉得文字"有AI味""像流水账""人物说话一个味儿"
- 长篇连载中需要定期体检：人设一致性、伏笔对账、时间线矛盾
- 配合 novel-writing-workflow 技能的第 7 阶段（修订）使用

## 核心规则

**五轮顺序不能乱**：先结构后文字。在结构没过关的稿子上润色是浪费时间。
每轮单独执行、单独出报告，问题按"必须改 / 建议改 / 可不改"分级，用户拍板后再动手改。

## Steps

### 第 1 轮：结构轮（砍场景）

对照 `03_大纲/总纲.md` 和本章章纲：
- 每个场景问一句：删掉它主线会不会断？不会断就标"建议删"
- 本章冲突是否成立？主角是否付出了代价？（无成本获胜=无效章节）
- 结尾钩子是否有力？

### 第 2 轮：逻辑轮（找 bug）

- 因果链：每个转折是否有前因？"角色为什么这时做这件事"答不上来的都是漏洞
- 时间线：对照 `01_世界观/时间线.md` 排查矛盾；物候/季节与意象是否自洽（如"冬天没有萤火虫"立过规矩就不能破）
- **代价真实性**：主角付出的代价在世界观内是否成立？誓言、口头承诺不算代价，机制性的损失（权力、利益、自由的可验证交割）才算。政治设定必须能承受推演（如：太子离朝会不会引发继承危机）
- 伏笔对账（双向）：(1) 正向——对照伏笔登记表，该回收的是否回收；(2) **反向**——扫描正文中出现 ≥2 次的道具/意象/称呼，凡未登记的一律补登记（实测中"正文有伏笔但表里没记"是正向对账的盲区）

### 第 3 轮：人设轮（OOC 巡检）

逐条对照出场角色的角色卡（静态设定）和角色状态.md（动态状态）：
- 台词：把角色的对话与角色卡"声线样本"比对，不像就标出
- 行为：是否踩了角色卡里的"恐惧/雷点"
- 口癖：该出现的没出现、不该出现的出现了
- **已知信息**：角色说了/做了 TA 此时不可能知道的事（对照角色状态.md，这是长篇最常见的穿帮）
- 状态连续性：伤势、物品、位置是否与角色状态.md 记录的一致
- **能力符合度**：角色的技能、语言、武力是否与设定一致（实测案例：把会武功的角色写得笨拙、把精通某语言的角色写成初学；说什么语言要随谈话对象走，不是随情节方便）
- **场合一致性**：人物在人前/私下/对不同对象的行为差异必须有动机支撑（实测案例：东宫太子公开宠爱某人=把对方变成靶子，"宠"只能走暗线；保护性冷落是权谋背景人设的标配）

### 第 4 轮：文风轮（去 AI 味）

按此清单逐项扫描，这是 AI 初稿的重灾区：
- **复读机用词**：同一形容词高频复现（真实案例：某 AI 小说"坚定"20 章出现 66 次）——用脚本统计词频，前 20 的高频修饰词逐个审
- **光明的尾巴**：每段生成内容自带小结尾/小总结，段与段之间像独立作文
- **形容词副词堆积**："他的目光中透露出一种沉稳和坚定"式句子
- **论文腔/说明腔**："值得注意的是""总的来说""换言之"
- **情绪直述**："他很愤怒"→ 应改为动作和生理反应呈现
- **人物同声口**：遮住人名分不清谁在说话
- **网络流行语 / 翻译腔**：对照 `07_文风规范.md` 禁用清单
- **控制性隐喻反噬**：一个核心比喻（如"他像台算计的机器"）反复出现会字面化人物，让人物读起来像比喻本身（实测案例：李承鄞被机器隐喻写成"人机"）。同一隐喻每章最多出现一次，且不许进入叙述者的定性判断
- **思维日志化**：人物思考写成"第一个念头…第二个念头…结论"式决策树。真人的挣扎是身体反应、自我辩解、冲动与克制的拉锯——把"分析过程"改成"门前止步"式的动作

### 第 5 轮：节奏轮（查注水）

- 冲突密度：超过 2 页没有冲突/新信息=注水预警
- 章末钩子强度：随手一翻到章末，想不想点下一章？
- 对白/叙述比例是否符合 `07_文风规范.md`

## 审校 Prompt 模板

人设巡检：
```
读 02_角色/角色卡_XX.md 和 05_正文/chXX.md，逐条比对：(1)台词是否符合声线样本 (2)行为是否触碰雷点 (3)口癖使用是否正确。按 必须改/建议改 分级列出，给行号和修改方案，先别动手改。
```

词频体检（可脚本执行）：
```
统计 chXX.md 中形容词/副词词频，列出前 20 个，标注哪些出现超过 5 次。
```

## Pitfalls

- 一次只跑一轮，输出报告后等用户确认再改，不要五轮混着来一次大改
- 润色不是替换同义词——要动句子结构和信息呈现方式
- 保留作者的"人味"：怪但有个性的句子不要改成平庸的通顺句
- 修订后必须更新正文文件头状态（draft→revised），并 git commit

## Verification

- 每轮有独立报告，问题分级（必须改/建议改/可不改）
- 修订稿通过全部五轮后，状态才能标 final
- final 章节同步更新 06_章节摘要.md
