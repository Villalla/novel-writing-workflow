# 小说创作工作流（2.0）

## When to use

- 用户要写小说/网文/同人，需要从零搭建或推进创作工作区
- 用户需要人机分工方案（避免「一键成书」水文）
- 长篇一致性：伏笔、人设 OOC、知情越界、时间线、外貌称谓漂移
- 用户提到批量草稿、必要检查、创作契约、作品备份仓库

权威落地文档（若工作区存在，以其为准）：`工作流手册.md`、`使用说明.md`、`工作流实践复盘_回归律.md`。

## 核心原则

**结构归人，细节归 AI**。立意、结局、人物锚点、取舍由人拍板；AI 负责整理、推演、扩写、检查。绝不默认「一键成书」。

**作者否决权是最终质量闸门。** 满意初稿时可只做必要检查并收束，不必为流程而精修。

## Steps

### 1. 搭建工作区

```
小说创作工作区/
├── 工作流手册.md / 使用说明.md
├── 00_立项书.md / 00_拆书_模板.md
├── 01_世界观/          # 同人 → 01_原著考据/ + 设定取舍.md
├── 02_角色/            # 角色卡（含稳定外貌/常服/称谓/不可辩护行为）+ 角色状态.md
├── 03_大纲/            # 总纲 / 卷纲 / 伏笔登记表 / 修订决策.md（创作契约）
├── 04_章纲/            # 含「知情边界」字段
├── 05_正文/            # 状态: draft / revised / final
├── 06_章节摘要.md
└── 07_文风规范.md
```

仓库分离：工作流模板 → `novel-writing-workflow`；单部作品材料 → 独立作品仓（如 `My_novel_storage`）。

### 2. 阶段推进（含 1.5 创作契约）

1 立项 → **1.5 创作契约**（`03_大纲/修订决策.md`：硬事实 / 灰区 / 暂不写死）→ 2 世界观或原著考据 → 3 角色 → 4 总纲 → 5 卷纲+章纲（章纲必填知情边界）→ 文风样例决策 → 6 正文 → 7 修订（默认必要检查）。

不要跳级写正文。长篇（15 万字+）必须过卷纲层。

**决策门**：总纲/章纲/文风样例产出后停下来等用户拍板。正文前先出 2–3 个文风样例（同场景各约 200 字），选定后写入 `07_文风规范.md`。

**总纲压力测试（定稿前）**：结局是否可挣得；仇恨深度 vs 篇幅；代价是否机制性成立；需要「全世界原谅」还是「当事人选择」；关键抉择是否符合人设惯性。

### 3. 写正文：两种速度

| 模式 | 何时 | 规则 |
|------|------|------|
| 精写 | 开篇、高潮、关系转折 | 可先出走向；分段确认；当天回灌 |
| 批量草稿 | 中段 + **作者明确授权** | 可一次多章；批末必须事实审校；不得拖到全书完才首次回灌 |

高光场景优先人写。卡文时只讨论不给稿。

### 4. 上下文打包（扩写时）

```
07_文风规范 + 本章章纲（含知情边界）+ 出场角色卡与角色状态 + 06_章节摘要
```

有则加读：`03_大纲/修订决策.md`、同人`设定取舍.md`。**禁止用正文全文替代摘要。**

### 5. 章后回灌

```
摘要 → 06_章节摘要.md
状态 → 02_角色/角色状态.md（含已知/未知、装束若有变）
伏笔 → 03_大纲/伏笔登记表.md（以正文为准回写）
必要时微调后续章纲 → 按仓库分别 git commit
```

批量模式可延后到每 3–5 章回灌一次。只有 `final` 章可作为后续既定事实。

### 6. 修订入口（转交质量技能时）

- 用户说「检查 / 审校 / 必要检查」且未要求润色 → **必要检查轨**（见 `novel-quality-review`）
- 仅当用户明确要求精修 / 去 AI 味 / 五轮审校 → **文学精修轨**

## Pitfalls

- 未填创作契约与知情边界就扩写 → 硬伤高发
- 未授权就批量成书；批量后不做事实审校
- 把「必要检查」做成全量润色
- 同会话自检有盲区：重要审校优先新会话 / 盲审 / 作者通读
- 角色卡缺「不可辩护行为」或稳定外貌/称谓 → 中后期漂移
- 工作流仓与作品仓混堆正文

## Verification

- 目录与关键模板齐全；`修订决策` 已起草或已确认可暂缓项
- 章纲含知情边界；角色卡含稳定细节与不可辩护行为
- 摘要/角色状态/伏笔与正文进度匹配
- 批量草稿后存在事实审校清单，且改动已经作者确认
